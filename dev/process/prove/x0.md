# X0: the probes that pick a diff

Run on 10 October 2026 on Sonnet with Claude Code 2.1.296, each call capped, the event lines kept under `probes/`.
Each answer picks one branch of a change before that change is written.

## (a) Does structured output arrive under the planner's exact flags? Yes.

`claude -p --tools Read,Grep,Glob --strict-mcp-config --output-format stream-json --verbose --model sonnet
--json-schema <the proposal schema> --session-id U -- <prompt>` on a report fixture: 9 events, the `result` event
carries `structured_output` with one node, `total_cost_usd` 0.036, 4 turns (`probes/a1.jsonl`). The strict schema
(`type: ["string", "null"]`, `additionalProperties: false`, taken from `nemotron/planner.py`'s FORMAT) is accepted.
The second try, `--resume U` with the same flags and a refusal in the prompt, carries `structured_output` again
($0.043, 2 turns; `probes/a2.jsonl`). **A1 adds the flag and reads the result event's `structured_output`; the
text-form fallback stays for any planner that prints text.**

## (b) Does `--max-budget-usd` count the attempt or the resumed session? The attempt.

With the cap at $0.03: a first turn costing $0.0185 succeeds; the resumed second turn costs about $0.020 on its own
and succeeds, while its reported `total_cost_usd` is $0.0386, the session's running total (`probes/b_cap03.txt`).
So the cap is checked against the invocation's own spend, and `total_cost_usd` is cumulative (what the meter
already treats as `reported`). A turn whose own cost passes the cap ends with `subtype: error_max_budget_usd`,
`is_error: true`, an empty `result` and exit code 1: the text is dropped (`probes/b.txt`, a $0.05 cap hit by one
$0.051 turn). **C1's cap reads "$2 an attempt" (CAP_UNIT = "an attempt"); a capped stop is recognised by that
subtype.** One cheap Sonnet turn costs about $0.02 because of Claude Code's own system prompt, so no cap under about
$0.05 lets a turn finish.

## (c) What does the shipped executor see, and do the hooks still fire?

One toy leaf (`probes/x0c.sh`) run by `graphene run` on 907a7d0's wheel, the executor line with:

| flags added to DEFAULT_WITH | MCP tools in the init event | slash commands | Ponytail (a user-level hook) in the stream | hooks fired in the worktree | cost |
|---|---|---|---|---|---|
| `--strict-mcp-config` | 0 (and `mcp_servers: []`) | 99 | yes, twice | yes: a session row from the hook, 1 prompt, 1 tool event | $0.065 |
| `--strict-mcp-config --setting-sources project,local` | 0 | 55 | no | yes: the same rows | $0.037 |

Both executors read the leaf's contract, declined to write outside its scope and handed the leaf back with
`--wants outside.txt`, which the record shows; neither tried the write, so `permission_denials` was empty both
times and whether a hook's deny also appears there is **not answered**. D1 leaves write tools to the hook's rows,
so a hook's write denial cannot be double-counted whatever the answer. **The shipped executor gets
`--strict-mcp-config` (the MCP servers go); the user's plugins and hooks still reach it, and the PR says so:
`--setting-sources project,local` would drop them too, and drops user-level auth and model settings with them, so
it stays out of the defaults for Alex to veto. Every experiment session uses both flags.**

## (d) Do readers get structured output with `--tools ''`? Yes.

`--tools '' --json-schema {answer: number, why: string|null}`: `structured_output` is `{"answer": 4, "why": "2 + 2
= 4"}`, $0.015, 2 turns (`probes/d.txt`). **X3's readers use the flag.**

## (e) Does this Claude Code list the flags? Yes.

`claude --help` lists `--json-schema`, `--max-budget-usd`, `--setting-sources`, `--strict-mcp-config`, `--tools`
and `--disallowedTools`.

## (f) Does `/batch` run headless? It stops to ask.

`claude -p '/batch add a one-line module docstring to every .py file under app/ that lacks one, one file per unit'`
with the plain session's permission flags plus `Agent Task EnterWorktree ExitWorktree` in the allow list, on a
fresh report fixture: 5 turns, $0.055, `subtype: success`. It read the repo, found one file lacking a docstring,
wrote its plan, noted it "couldn't enter plan mode (the tool isn't available in this session)", and ended its turn
asking "Decision for you … (a) run the batch as planned with one worker, or (b) just make the edit here directly.
Which do you p…". No subagent was spawned (`subagent_stats.spawned: 0`), nothing changed, no branch or worktree was
made (`probes/f.txt`). One Bash call (`find … | while …`) was denied for not matching the allow list. **X2(c)
sends the approval as a second message (`--resume`, "Approved: run the batch as planned"), which is the person's
step, and records it as such; if workers still do not start, the arm is reported as "could not run headless" and
scored nothing.**

## Two harness notes

- `zsh` does not word-split an unquoted variable, so a `$FLAGS` holding `--session-id U` reaches `claude` as one
  argument and is refused as an unknown option. The harness scripts are `bash`.
- The clone's `dev/test/newrun.sh` has no executable bit; the scripts call it with `bash`.
