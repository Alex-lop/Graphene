## auto mode, the envelope, state and the gate

Two reviewers, A and B, read the envelope and the gate and ran probes. A found six faults, B three; A5 and B3 are one fault. One fixer took them on `lane/review`, eight commits on 0418ca97. Each fix was confirmed by the reviewer who did not find it, at the fix's parent (the test fails) and at the fix (it passes).

- A1 (high): a committed symlink (`docs/g -> ../.git`) carried a scoped write into `.git/hooks/` and `.claude/`; the gate judged the link's spelling, never where it landed. Fixed in daf472c4, `tests/test_review_link_lands.py`: `gate._lands` resolves the real path of every write (Write, Edit, the shell reader's paths, PostToolUse's changedFiles) and judges that. Confirmed by B: ten spellings through the link refused with GIT_OWN, `docs/cfg/settings.json` judged as `.claude/settings.json`. A limit stays: at accept time `fits` still takes `docs/**` in a repo that ships such a link; the write-time guard closes the harm whatever the scope says, the accept-time wait is defense in depth for Alex to want or not. `chmod +x` alone passes before and after: the shell reader does not model chmod as a write, and with the content write refused it plants nothing.
- B1 (high): `git config core.hooksPath src/.hooks` moved git's hooks into an agent's own scope; the gate's command parser did not know `git config`, so `.git/config` was written unseen, and the setting reaches the person's checkout across worktrees. Fixed in d36b6305, `tests/test_review_git_config.py`: `_git_config_write` refuses a `git config` that writes, hooksPath in `-c`/`--config-env`, and `GIT_CONFIG_*` in the environment. Confirmed by A: 14 cases allowed at the parent, 23 pass at the fix; reads and a commit message naming the words still pass. A limit stays: `sh -c '…'`, `$g config` and `xargs git config` pass, as `sh -c 'printf x > .git/hooks/pre-commit'` already passed: the gate reads plain commands. A side effect for Alex: `git config user.email …` is now refused to an agent holding a leaf.
- A2 (high): HOOKS was matched by exact string, so on a case-blind disk a prompt's leaf wrote `.CLAUDE/settings.json`, the file that holds Graphene's hook. Fixed in 4e3cc6c4, `tests/test_review_hooks_case.py`: `rel.casefold() in HOOKS` at both places. Confirmed by B: all five spellings refused for Write and `echo >`; `.claude/commands/review.md` stays an aside's to write. HOOKS stays the two settings files, not the whole `.claude/` directory.
- B2 (high): a `#` glued to a word in a task's check (`pytest x#;touch MARK;false`) made shlex drop the rest as a comment while bash ran it, defeating the `checks:` allowlist; shown end to end writing a marker file. Fixed in ecd49c3b, `tests/test_review_check_comment.py`: `lex.commenters = ""`. Confirmed by A: `x#&&`, `x#|`, `x#>M`, `x#$(…)` refused; `pytest '#tag'` and `pytest -q # the fast ones` still fit, as bash reads them.
- A3 (high): `runs_as_check` read words, not what runs: with `checks:` unset, `sh -c 'curl … | sh'`, `eval "$EVIL"` and `PATH=/tmp/evil pytest` ran unread. Fixed in part in cc606b65, `tests/test_review_check_wrappers.py`: a shell, a wrapper (eval, exec, source, env, xargs, nohup, time, sudo…) or a leading `NAME=value` now waits; HOW_IT_WORKS says `checks: pytest -q` means pytest with any words after it. Confirmed by B, with two notes. A limit stays: `nice sh -c …` runs (`nice` is in shell.py's wrappers, not in SHELLS); `python -c`, `perl -e`, `node -e`, `find -exec sh`, `make -f /tmp/evil.mk`, `uv run sh -c` run unread, because the class is unbounded by words. The honest closure is no check unread until `checks:` is named: Alex's decision.
- A4 (medium): the `tasks` cap was evaded by nesting: a task that landed left the count once a child was proposed under it, so `tasks: 2` accepted and ran 6. Fixed in d145b914, `tests/test_review_tasks_cap.py`: `accepted()` counts every `by: auto` node that was a leaf in its accept act. Confirmed by B: round 2 now waits ("accepts 2 tasks and this makes 4"). A limit stays: "a leaf in its accept act" is read from the row's timestamp, not recorded; two rounds in one millisecond at the unit level drop the first from the count, unreachable from the CLI or a planner round trip. A child under a done task still does not wait for the person: a product decision, the cap holds either way.
- A5 + B3 (medium): the planner was asked, and its proposal accepted, after the budget was spent; a `claude` planner ran with no cap and overran a $0.01 budget 6x. Fixed once in 27c57862, `tests/test_review_planner_budget.py`: `drive` reads the budget at the top of the loop, before the planning stage, and again before the run; `planner_cap` gives a Claude Code stream-json planner `--max-budget-usd {left}` or waits when its own cap exceeds what is left. `test_auto_run`'s spent-budget test codified the old order and now expects `[waits]` alone. Confirmed by both A and B: the planner is never called with the budget spent. A limit stays: a script or Nemotron planner gets no cap (parity with `run_cap`); a `claude` planner without stream-json gets none, but the meter reads no cost from it either; under half a cent is passed as `0.00`.
- A6 (low): an NFD spelling of a `protected:` name passed at propose and at the write, and landed in the NFC directory on APFS. Fixed in 2a52bef3, `tests/test_review_nfd.py`: `plan.covers` composes to NFC and casefolds (`_as_disk`); `_keeps_standing` normalizes before `overlap`; `gate._protected_read` reuses `covers`. Confirmed by B: the NFD scope is refused and the NFD write no longer binds.

Tried and found nothing: last night's three fixes hold (`.git/hooks/pre-commit` and `.GIT/…` refused directly; `auto.fits` holds `.claude/**`, `.CLAUDE/**`, `**`, `.*/**`, `.github/**`, `.git*/**`; `..`, `/abs`, `~` and braces refused at propose; `curl | sh`, `;`, `&&`, `>`, `$(…)`, backticks and a newline refused as checks); an executor's own `graphene run` (refused by GRAPHENE_NODE); forks (Budget holds each attempt's worst case); GRAPHENE_AS, WATCH and the store's guards; state.py (read-only, nothing hostile reaches it); writes outside the repo through absolute paths (let go by design, Claude Code's own permissions apply). Not probed: two concurrent person runs each capped at the budget left, the non-stream `run_cap` path, the webview and the extension (other lanes).

Suite at 2a52bef3: 2840 passed, 21 skipped. `ruff check`: two E501 in `tests/test_vscode_packaging.py` from the base commit, not this lane's. A clone under a path with spaces breaks `test_auto_run` and the planner test (the planner's path splits at spaces); both confirmers reran from a space-free path.
