**The product, one sentence.** The local map of what your coding agents did to your repo: every agent, task, file, commit and check drawn from the records, with an honest count of what it cannot account for, and the place where you set the boundaries the next run must obey.

**Who.** The developer who delegates in bulk (subagents, worktrees, Workflow fan-outs, overnight) and comes back to tens of commits with only the agent's own summary to go on. You. The default screen is the morning after; live is the same screen with the scrubber pinned to now.

**The three questions.** (1) Who did what: which agent, asked what, in which worktree, changed which files, in which commits. (2) How much is accounted for: files traced to a recorded write / only to an agent's commit / to nothing. (3) What the diff hides: abandoned work, failed checks, refused calls, writes outside the repo, two agents on one file, rules that fired.

**What I found using it.** On Nemisis, `graphene why` said "no recorded prompt" for your three most-committed source files. Here, the release card says 11 files; git says 40. Causes, checked in the store: worktree edits are filed under "outside the repo"; most source changes never pass through Edit/Write at all (last night's main transcript: 147 Bash calls, zero Edit/Write); nothing records which agent spawned which or what it was asked. Line-level `why` was right 6 of 6 when it answered. A dry run of the fixes on real data: last night's session goes from 11 of 40 files to 40 of 40; Nemisis's big session reaches about 70%, and the map has to show the rest as unknown.

**What the graph is.** A time-lane map, not a web of bubbles. Time left to right, agents as lanes (subagents branch off their parent like a git graph), the repo as directory rows underneath, marks where an agent touched a file, a scrubber for replay and live. Select anything and its chain is drawn as a small node-link diagram: task → agent → files → commits → checks. Positions are computed in Python from the records, so nothing jitters and the layout is tested in pytest. I am overruling the bubble graph on evidence: the one file-graph in the market has 4 stars, and the test user said it would make them close the tab in ten seconds. The live graphs that spread (zoetrope, 909 stars in a month) show agents only; ours adds files, commits and the unknown.

**Collaboration = five interactions, each true by mechanism, each printing what it cannot do (night three).** Protect a directory (hook deny + the vendor's own `Edit` deny rule + the sandbox if you use it; a script that slips past is detected and shown as a breach). Finish gate (Stop hook blocks while a recorded check is failing or stale; asks twice, then lets go). Note pinned to a path (injected when an agent touches it; labelled a note; delivery receipt). One writer at a time per file among agents sharing a checkout. Stop a run. Rejected because they cannot be made true: editing the agent's plan, pausing, assigning work, approve/reject.

**Cut.** `--explain`/`--model` (a model's sentence beside facts breaks law 2), `--html` and its template (replaced by `graphene ui --export`), `--md`, `--full`; `debrief` and `ingest` hidden. Visible: `graphene`, `graphene ui`, `graphene why`, `graphene sessions`, `graphene init`. `init` becomes the install step (30-day sweep; hooks see more; rules need it).

**Tech.** React + TypeScript + Vite, SVG, d3-zoom, no graph library (layout is data; a library sells layout and dragging, which we forbid). Cytoscape rejected on merit, not history. Built assets committed inside the package; no Node at install or run. Live = server-sent events from a stdlib loopback server polling SQLite; the hook never talks to it.
