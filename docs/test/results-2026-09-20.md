# The collaboration test: results, 20 September 2026

Twelve runs: three tasks, two arms, two repetitions each. A different sub-agent stood in for the
person in every run. This file was written by an auditor who re-ran `tally.py` on all twelve repos,
read all twelve run logs and stores, and checked the hidden acceptance by hand for two of them.

Every number below comes from `docs/test/summarize.py`, which calls `tally.py` per run and reads
the stores. Nothing was counted by eye.

```sh
python3 docs/test/summarize.py <the directory holding the twelve run directories>
```

## The question

From the collaboration directive: *for the same task, does a person working through Graphene get
fewer files touched outside intent, fewer "no, not that" restarts, and less rework than the same
person with a prompt and a diff?*

## The protocol in five lines

1. Both arms get the same private card, run `graphene init`, and get three corrections and no more.
2. Paragraph arm: one opening prompt of 90 words or fewer, then follow-up messages; each follow-up
   that says "no, not that" spends a correction.
3. Plan arm: an opening ask of 30 words or fewer plus "propose a plan with `graphene plan propose`",
   then the person edits the proposed nodes' goal, scope, check and owner, which is free.
4. The executor in both arms is `claude -p --model sonnet --permission-mode acceptEdits` with the
   same tool list. The person reviews by reading the diff; the hidden acceptance is run afterwards.
5. A run that goes wrong is reported as it went; nothing is tuned once a run has started.

## What the paragraph arm won on

Saying this first, because it did.

- **Effort.** It took fewer person actions in every task (median 4 against 9) and fewer typed
  characters (median 896 against 1342) — and the plan-arm character count is a lower bound, because
  three of the six plan-arm logs summarise the commands the person typed instead of quoting them.
  One of those runs says its real figure is 1924, not the 983 recorded.
- **Cost and time.** Lower in every task: median $0.18 against $0.26, 133 seconds against 254.
  Three plan-arm cost figures are lower bounds, so the gap is wider than printed.
- **Rework, as `tally.py` prints it.** On the `logs` task the paragraph arm shows 10 and 6 lines
  against the plan arm's 26 and 20. That number turns out to be wrong — see below — but it is what
  the harness produced, and it is wrong in the plan arm's disfavour.
- **Restarts on `inventory`.** 0 and 0 against 0 and 1. The one restart is a plan-arm node reopened
  because the new command was added to the table but not to the usage line.
- **Code the numbers do not look at.** On `logs`, both paragraph-arm parsers use a regular
  expression that requires an ISO timestamp and an uppercase level, and strip the trailing newline.
  Both plan-arm parsers are `line.split("|", 2)` with no check on either field: `garbage|not|a
  timestamp` comes back as a parsed log line, and the message keeps its `\n`. The card says
  anything that is not the new format returns `None`. Neither the node's check nor the hidden
  acceptance catches this, so it appears nowhere in the table.

## What the numbers show

1. **Nobody failed anything.** All twelve runs passed every hidden check: 9 of 9 on `report`, 11 of
   11 on `inventory`, 10 of 10 on `logs`, in both arms, both repetitions. Each task was built around
   a trap — a totals object in a data feed, a business number an agent must not pick, a change of
   mind — and sonnet avoided every trap in every run of both arms. On outcome, this test separates
   nothing, because there is nothing left to separate. Two acceptance results were re-checked by
   hand against the repo (report-prompt-2 and logs-graphene-1, 19 checks between them) and both
   agree with `accept.py`.

2. **Files touched outside intent: zero everywhere, on the final diff.** In the plan arm that is
   close to a tautology: the person set each node's scope to the paths the card names, and those
   are the same paths `intent_globs.txt` holds, so "outside intent" and "outside scope" are the same
   set and a write outside it is refused. The paragraph arm had no such guarantee and scored zero
   anyway, in all six runs. Counting every file written at any point rather than only what survives,
   the plan arm is one worse in both `logs` runs: its executor wrote `.plan-logs.json` /
   `.plan-tmp.json` inside the repo to feed `graphene plan propose`, then deleted it.

3. **No write was ever refused.** `refused_writes` is 0 in all six plan-arm runs, and the stores
   confirm it: no `denied`, `breach` or `refused` entry in any `node_log`. The enforcement path was
   never exercised. Whatever the plan arm did here, it did at plan time.

4. **Restarts: no difference outside `logs`, and the `logs` difference is partly a definition.**
   Overall median 0 in both arms. On `logs` it is 1.5 against 0 — but the protocol itself (the
   paragraph arm's rule 5 against the plan arm's rule 7) says the card's change of mind *costs the
   paragraph arm a correction and costs the plan arm nothing*. One of logs-prompt-1's two and the
   whole of logs-prompt-2's one is that mandated change of mind. That leaves exactly one restart in
   twelve runs that is a real "no, not that": logs-prompt-1 asked for a count per hour, got
   `2026-09-20T10` buckets, and had to say "the hour itself, not the date plus the hour". The plan
   arm avoided it by writing `"HH count" (the hour is the HH of the event timestamp:
   2026-09-20T09:14:02Z is hour 09)` into the node's goal. That is a wording difference between two
   stand-ins, and nothing in it required the tool.

5. **Rework: the printed number is wrong on `logs`, in the plan arm's disfavour.** `tally.py`
   reports 26 and 20 lines of rework for the two plan-arm `logs` runs. All of it is the plan scratch
   file: the store holds it once as a `Write` of 13 (or 10) lines and again as the `rm` in the Bash
   change list of `graphene plan propose … && rm …`, and both are added to recorded churn while
   neither is in the final diff. With those files removed, both plan-arm `logs` runs rewrote **0**
   lines of code and the two paragraph-arm runs rewrote 10 and 6. That is the `rework (code)` column.
   It is the one number in this report that moves in the plan arm's favour, it was found while
   trying to make the plan arm look worse, and `tally.py` should be fixed before anyone quotes a
   rework figure again.

6. **The plan arm typed more, spent more and took longer**, in every task, on every effort measure.

7. **The plan arm's executor was told about twice as much.** Median specification reaching an
   executor: 551 characters in the paragraph arm against 1116 in the plan arm, and 1395 on
   `inventory`. The 90-word cap binds the paragraph arm; nothing caps shaping. Two plan-arm checks
   contain the acceptance criteria as executable code, and logs-graphene-1's check contains the
   program's exact expected output:
   `test "$(python3 -m parser.cli samples/app.log)" = "$(printf "09 2\n10 3\n11 1")"`. Graphene
   hands the check text to the executor word for word, so in that run the executor was shown the
   answer. This is allowed by the protocol as written. It is not the same amount of help.

8. **The one thing the plan arm demonstrably did.** In both `report` runs the agent's own proposal
   contained two of the card's reject-on-sight items: a `totals` object in the feed, and
   `tests/test_report.py` — the file that *is* the text format — inside the node's scope
   (report-graphene-2 also asked for `README.md`). The person removed both by editing the plan,
   before any code was written; the store's `node_log` records the exact before-and-after. In
   report-graphene-2 the person did this without ever writing the word "totals" in prose to the
   executor. But report-prompt-2's person deliberately left the no-totals constraint out of the
   paragraph, and that executor produced no totals either. The plan removed a risk that did not
   materialise in the other arm.

## What the numbers do not show

- They do not show that working through a plan produces fewer files outside intent, because the
  paragraph arm touched none either, on any task, in any run.
- They do not show fewer restarts. One restart in twelve runs is attributable to anything other than
  the protocol's own bookkeeping.
- They do not show less rework once the tally defect is corrected: on `report` and `inventory` both
  arms rewrote nothing, and on `logs` the corrected figures are 0 against 10 and 6, from n = 2.
- They do not show that the enforcement works, because it never fired.
- They do not show anything about outcome quality, because both arms scored 100% on every hidden
  check — and where quality differs (the `logs` parsers), it differs in the paragraph arm's favour
  and no metric records it.
- They do not measure a person. Every "person" here is a language model with the card in its
  context, typing at machine speed.

## Threats to validity

- **The stand-ins are language models**, and they had the card in context while writing their
  prompts. Phrases from the card appear in the paragraphs almost verbatim ("finance sums their own
  columns"). A person recalling the same card would say less, and less precisely.
- **The stand-ins knew the hypothesis.** Each was told which arm it was in and what the test was
  measuring. Several said in their own notes which way they thought a choice cut.
- **The repositories are toys**: 13 to 15 files, changes of 14 to 33 lines in two or three files.
  There was nothing for a scope to hold back, which is why nothing was refused.
- **n = 2 per task per arm.** Every "median" above is the average of two numbers. Nothing here
  survives a single different draw.
- **The tool's author designed the test**: the tasks, the intent globs, the hidden acceptance, the
  metric definitions and the rules for what counts as a correction. Two of the four headline metrics
  are defined so the plan arm cannot lose them — "outside intent" equals "outside scope", which the
  hook enforces, and a change of mind counts as a restart in one arm and not in the other.
- **Sonnet as executor got everything right**, in both arms, in all twelve runs. That is a ceiling,
  and any difference between arms is under it.
- **Run isolation failed.** Executors in report-graphene-2, inventory-graphene-1 and
  inventory-graphene-2 wrote their proposals to `/tmp/*.json`; report-graphene-1's executor wrote
  one into the shared test directory. Both `logs` plan-arm executors then read a stale
  `/tmp/plan.json` and proposed a `json-report` node belonging to the `report` task, which the
  person had to drop. The runs were not independent, and the two `logs` plan-arm runs each paid a
  person action for someone else's leftover.
- **`tally.py` cannot see a write outside the repository.** report-graphene-1's executor wrote a
  file in the shared test directory and no number in this report counts it. An agent that writes
  outside the repo is invisible to this harness in both arms.
- **Three plan-arm cost figures are lower bounds** (report-graphene-1, report-graphene-2,
  inventory-graphene-2): `graphene run` captures its executor's output and discards it, so only the
  proposal call reported a cost. inventory-graphene-1 is the only plan-arm run with a complete cost,
  because its stand-in put a wrapper script named `claude` on the path — and it is the highest
  plan-arm cost in the table.
- **Three plan-arm run logs summarise the person's commands** rather than quoting them, so
  `person_chars` understates the plan arm's typing. inventory-graphene-1's own notes give 1924
  against the 983 recorded.
- **One run log is out of order.** inventory-prompt-2 wrote its `handwork` entry before the executor
  result it followed; the timestamps are correct, so no number is affected.
- **The paragraph-arm prompts are dense.** They name files and identifiers (`app/report.py`,
  `policy.MIN_STOCK`, `OutOfStock`, `tests/test_report.py`). The rules forbid pasting the card and
  listing globs, not naming files, and the cards name those files — but these are not average
  Tuesday paragraphs. One stand-in said so itself.
- **Five runs had an infrastructure rerun**: the first `claude -p` call exited 1 because the prompt
  was passed after the variadic `--allowedTools` and was consumed by it. Nothing had been written,
  the same prompt was re-issued, and every affected run declared it. Rule 9 allows this.
- **All twelve runs ran on one machine, eight of them overlapping in time.** `wall_seconds` includes
  contention, and in both arms it spans an agent's pace with tool-call latency, not a person's.
  Cross-arm wall time here means very little.
- **Neither arm's review was purely reading.** Most stand-ins ran the repository's own test suite
  during review, in both arms. Nobody ran `accept.py`; the stores and run logs show no sign of it,
  and no node scope matches `intent_globs.txt` in a way the card does not already explain.

## What a real person should run next

1. **A task the paragraph arm can lose.** Everything here was a one- to three-file change that
   sonnet got right from a paragraph. Use something that spans five or more directories, where 90
   words cannot name the files and the agent has a reason to wander: then a refused write can
   actually happen, and `refused_writes` stops being zero.
2. **Fix the three harness defects first**, or the next numbers will be wrong the same way:
   `tally.py` double-counts a file that appears in both a write event and a Bash change list, and
   counts a scratch file created and deleted by one command; `graphene run` has a `logs` path the
   CLI does not expose, so executor cost is unmeasurable through it; and `graphene plan propose`
   invites executors to write a temporary file wherever they like, which is how one task's node
   ended up in another task's plan. Give each run its own `TMPDIR` and run the arms one at a time.
3. **Decide whether a node's check may state the answer.** As it stands the paragraph is capped at
   90 words and the check is not capped at all, and the executor is shown both. Either cap the
   shaping too, or drop the cap on the paragraph and compare like with like.
4. **Count something acceptance does not.** Run each arm's finished code against inputs it was never
   shown — the `logs` parsers differ sharply under that test and the current scoreboard is blind to
   it.
5. **Stop counting the change of mind as a restart in one arm only**, or report restarts twice: once
   as the protocol defines them, once with the mandated change of mind removed from both.
6. **Then run it himself, once, on a real repository, with a timer**, using the ten-minute recipe at
   the top of `docs/test/PROTOCOL.md`. Two arms of one task by a person who did not know the
   hypothesis would be worth more than these twelve.
