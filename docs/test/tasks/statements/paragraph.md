We're starting to bill in euros and pounds, so the statements need to handle more than one currency. Every posting should carry a currency. Everything already in the database is dollars, so the migration that adds it has to backfill USD. Balances are per currency, never add two currencies together, and a statement gets one section per currency, each with its own opening balance, postings and closing balance. Customers read the statement, so apart from the sections I want it to look the way it does now. `post` should take a --currency flag and `load` a currency column, both defaulting to USD so nothing that calls them today has to change. Finance wants half-even rounding everywhere now, banker's rounding, no exceptions. A few things can't break. The monthly totals file from legacy/monthly.py gets diffed by a cron job in the billing-ops repo, so it has to print exactly what it prints today, byte for byte. The v1 JSON export is what billing parses: as far as they know it's dollars only, and its shape can't change. scripts/close_month.sh has to keep passing, ops runs it on the 1st. Don't touch anything under vendor/, it's pinned to what the billing image ships. Migrations are numbered and applied in order, and the README in migrations/ has the rules. Please add tests for the new behaviour. I haven't been in this code for months and I honestly don't remember where everything lives, so you'll have to find your way around.
