# The second collaboration test: results, 21 September 2026

Nine runs of one new task, two arms, two person styles, two repetitions, plus four runs of a
separate keystroke comparison. One run is void and says why. A different stand-in played the
person in every run, and no two executors were ever in flight at the same time.

The `graphene` under test is a wheel built from **563c1f62151e9f4bdaf004f550cc6ff3b90a92f0** (the
tip of `tree` when this started) and installed into a venv whose `bin` was first on `PATH` for
every command, executor hooks included. It is not the editable install in the main checkout, which
was at 0.4.0 and being edited all night by somebody else. The one run that lost that isolation is
the void one.

Every number below is produced by one command over the run directories:

## The question

From the collaboration directive: *for the same task, does a person working through Graphene get
fewer files touched outside intent, fewer "no, not that" restarts, and less rework than the same
person with a prompt and a diff?*

From the tree directive, the sharper one: *how much work does a person hand off per unit of their
own attention, and was the result right?*

## What changed since 20 September

The auditor's list at the end of `results-2026-09-20.md` was the specification. All of it was done.

1. **A task a paragraph can lose.** `feeds`: a price-feed loader in 27 files. Loading the new XML
   supplier needs a reader in `ingest/`, a field map in `normalize/`, a rule in `validate/`, a name
   in `config/`, the usage line in `cli/` and a test — six directories — and the card names none of
   them, because the person has not opened the repository in a year. The README documents half the
   wiring and has been stale since the config file was added.
2. **A quality measure the acceptance cannot see.** `tasks/feeds/quality.py`: twelve feeds the code
   was never shown, each an instance of a rule the card states rather than an example it gives.
3. **Two person styles in both arms.** `dense` and `tuesday`, generated from one template by
   `standin.py` so the two briefs can be diffed.
4. **The three harness defects fixed**, with tests: churn counted once per file, transient files
   kept out of rework, executor cost read out of `.graphene/runs/`. A fourth was found and fixed
   too: a write inside `.graphene/worktrees/<node>/` is a write to the file it names, without which
   a parallel run measures nothing at all.
5. **Arms one at a time, each with its own `TMPDIR`**, and proposals fed to `plan propose -`.
6. **Restarts reported both ways**, and a third count that asks nobody to judge anything.
7. **Neither arm capped.** The decision, and why, is rule 3 of `PROTOCOL.md`.
