# Known limitations

This list describes the reviewed release. A limitation moves only when code, deterministic verification, and any required external proof all exist.

| Area | Current status | What closes it |
|---|---|---|
| Real Gemini workers | **VERIFIED LIVE.** On 2026-08-23, 9/10 ordinary and 3/3 controlled-failure missions completed end to end against the narrowed North Star target; evidence in `evidence/convergence/2026-08-23-completion-gate/` | — |
| Legacy mission stores | A mission whose final result bundle was registered **before** the store became the bundle authority carries no `FinalBundleVerificationReceiptV1`, so it now fails cold verification by design — the store cannot retroactively prove it recomputed a bundle it had no authority over. The 2026-08-23 night store is affected; its durable record is the committed capsule, which still cold-verifies | Nothing: the rule is correct and is not weakened for legacy data. Re-run the mission on the current build if a verifiable store is needed |
| Capsule vs store bundle audit | `mission capsule verify` does not run the store's `_verify_final_bundle_events` audit, so a capsule exported from a mission with a final bundle is checked for internal consistency but not for the bundle-verification receipt | Fold the bundle-event audit into capsule verification; it is a smaller proof gap, off the demo path |
| Full-matrix hang under load | Roughly two full-matrix runs in ten wedge after the last test item, printing a pass count and then hanging with no traceback. **The previously recorded SQLite root cause is withdrawn as unsupported:** every mission-store connection is opened with `sqlite3.connect(..., timeout=5)` and `PRAGMA busy_timeout=5000` (`backend/graphene/orchestration/store.py`), so no mission-store call can wait forever, and the reported stacks contain no blocking SQLite primitive. The mechanism is under investigation on a separate reliability branch and is **not claimed here**. One concrete asymmetry is visible in the tree and is worth reading first: `backend/graphene/orchestration/scripted.py` takes a blocking `flock(LOCK_EX)` on an attempt lock, while `backend/graphene/lineage/observation.py` uses `LOCK_EX | LOCK_NB` for the same job. `faulthandler_timeout = 180` still produces a stack dump | A reproduction that names the mechanism, and the fix that follows from it — not another guess |
| Generic repositories | Narrow initialized-repository runtime exercised locally with fake ADK workers; general support remains unproven | Published repository/runtime matrix plus adversarial scope and live execution proof |
| Fake-ADK vertical slice | Two workers reach exact `awaiting_result` without touching the source checkout and register the pending bundle | Add both terminal decision branches to one end-to-end fake-model matrix |
| Docker execution | **NOT PROVEN** on a responsive daemon; `GRAPHENE_CHECK_EXECUTOR=host-sandbox` is the verified macOS alternative for `fixture-tests` checks | Immutable image build and opt-in smoke on the selected host |
| Result inspection/export | `mission result show/export` verifies the V2-bound candidate and writes a create-only private patch; the stable release matrix is green | Live operator capture |
| Replay final decision | Pending-candidate checkpoint and simulated continuation exist; replay is not V2 bundle proof | Public capture; replay remains fixture proof, not live execution |
| Product media | Metadata present; PNG/GIF missing | Verified replay PNG plus reproducible GIF or documented capture-tool blocker |
| Browser commands | CSRF, idempotency, stale-state, attribution, finalizer, cancellation, and disabled-mode tests pass; private input remains hidden and live proof is pending | Safe staged-input cleanup plus captured verified operator flow |
| Task input | `graphene task input` commits only a digest-bound reference; the browser seam is tested but hidden in one-command live mode | Add safe staged-input cleanup before injecting the browser coordinator, then capture the flow |
| Hard budgets | Attempt, worker-time, and artifact exhaustion commit actionable `blocked_budget` state; no live resource-pressure demo | Exercise replan/cancel recovery in the recorded live path |
| Ordered write-scope transfer | Plan validation rejects two work tasks that declare the same write path **even when one depends on the other** (`ordered_write_conflict`, `backend/graphene/orchestration/validation.py`). An ordered ownership transfer of one file is safe in principle and is still refused; the rule is blunt on purpose and is not relaxed for the demo | An explicit ownership-transfer contract naming the handing-over and accepting tasks, with a regression that no third task can slip between them |
| Cancellation after a passing check | A cancellation is a `BaseException`, so it bypasses every failure handler and the attempt reaches the store as a bare `cancelled`/`outcome_unknown`. The attempt's evidence chain now carries a non-terminal `operation.failed` event naming the stages it completed and whether the acceptance check had already passed. **That event is not linked from the attempt row**, because the runner — not the runtime — decides between `cancelled` and `outcome_unknown`, so `graphene why` does not surface it; it is found by recomputing the attempt's evidence id | A stage field on `AttemptResult` so the mission event and `why` can name the stage directly |
| Replanning | Request command only; `request-replan` generates no linked replacement revision and nothing asks a model to produce one. The **user's** edit path is complete — `plan export` → edit → `plan revise` → `plan lint` → `plan diff` → `plan approve` — and produces an immutable revision N+1 with a new digest that needs its own approval. Editing after any attempt has been claimed fails closed | Model-proposed revision generation, if it is ever wanted; mid-mission revision of the remaining graph remains the tested store primitive behind `allow_after_dispatch` and is not reachable from the terminal |
| Artifact closure | V2 envelopes bind direct inputs and accepted publications; transitive `delta`/`cumulative_snapshot` subsumption is not supported | Add closure semantics only when a real plan needs non-flat artifact ancestry |
| Repository mutations | Generic workers support bounded create/update/delete/rename/chmod on regular `100644`/`100755` files; runtime/assembly/final-tree and scripted deletion paths are tested. Symlink/submodule mutations fail closed | Broader repository matrix plus live provider proof |
| Retention | Metadata only; no automatic expiry and purge | Tested purge/retention implementation and operator controls |
| Owned idle STDIO MCP cleanup | Missing | Strong ownership registry and lifecycle tests |
| Firestore cloud scheduler | Official emulator production vertical passes create/approve/readiness/claim/heartbeat/completion/materialization; it is not a full `SchedulerStore` | Add worker revoke/expiry/recovery, generic scheduler completion, awaiting-result, pause/resume/cancel, gate/final parity, then run the shared corpus |
| Cloud-to-local executor | Typed protocol, packaged coordinator, OIDC HTTPS client, artifact fetch, and local executor loop pass credential-free tests, and a **successful** single-executor round trip now runs against the official Firestore emulator including seeding. Abandon is **disabled** (501 `ABANDON_UNSUPPORTED`) and a second concurrent executor session is **refused** (409 `MULTI_EXECUTOR_UNSUPPORTED`); cloud parallelism is not claimed | Live authenticated cloud-to-local reconnect/result proof; the transactional-head redesign before multi-executor can be re-enabled |
| Cloud check authority | `executor_attested`. The coordinator recomputes a receipt's bindings, not its test results, so an authenticated remote executor is part of the trusted computing base and a hand-built passing receipt with arbitrary digests is accepted by design. Every successful cloud completion records `check_authority: executor_attested` inside the hash chain | Deterministic server-side check execution with server-minted receipts |
| Cloud Run/Firestore | **NOT DEPLOYED.** Billing is enabled on the configured project but Cloud Run, Cloud Build, Artifact Registry, Firestore and IAM APIs are all disabled, and the configured project is a Gemini-API auto-created `gen-lang-client-*` one rather than the dedicated sandbox `docs/ALEX_CLOUD_SETUP.md` requires. Nothing was enabled or created | The owner chooses the project, then the ordered command list in `CONVERGENCE_REPORT.md`; a mission still cannot be seeded into Firestore by any CLI, which is a software gap, not a cloud one |
| Cloud streaming | Per-client two-second polling | Shared listener/fan-out with measured behavior |
| Cloud artifact authority | Executor-local durable spool only; cross-executor transfer is unsupported | Reviewed private object storage and cold-restart recovery |
| Resource Sentinel | The product Gemini scheduler commits sampled-pressure decisions and a credential-free path proves reduced then restored dispatch. Unsupported/non-owned process sampling stays unavailable | Capture pressure/action evidence in a live provider run |
| V2 artifact/final bundles | Successful publications require V2 envelopes; an immutable pending final bundle is registered before display/approval/rejection, and both decisions bind its ID | Live operator proof only; no format expansion is needed for this release |
| Taskmaster causal query | `graphene why PATH --mission MISSION_ID [--json]` verifies current mission authority and reports committed links with worker identity, fences, retries, receipt nodes, and unknowns | Richer TUI navigation and broader query shapes |
| Mission capsule | `graphene mission capsule export/verify` cold-verifies internal consistency from the capsule bytes; it carries no signature, so producer authenticity is not verified | Signed capsules only if a trust model for the signer exists |
| Failure laboratory | Deterministic SIGKILL choreography proven with fake ADK workers on macOS; cancel during an attempt's model phase has no owned process and aborts. Separately, `graphene mission start --inject-check-fault` fails the first trusted check once with a `simulated_fixture` receipt, and 3/3 live missions recovered and completed through it | Live SIGKILL run with Gemini workers that also completes; owned identity for the model phase |
| Shadow Agent | ndjson and claude-code adapters verified on synthetic fixtures; the one real Claude Code transcript is private, so its ingest is a counts-only smoke, not a reproducible proof; ingestion is never tamper-evident about its source | A shareable real transcript, or a scrubbed capsule exported from one, committed with the report |
| Graph-economics benchmark | Harness and equal-gate contract are tested; results **NOT PROVEN** | Real repeated equal-quality runs with raw receipts, median, and P95 |
| Comprehension study | Not run | Five-person protocol in [Graph necessity evaluation](GRAPH_NECESSITY_EVAL.md) |
| Public demo/video | **NOT PROVEN**; not recorded. `graphene demo --live` now orchestrates the whole sequence in one terminal and every constituent verb has been executed live, but the single continuous run has not been performed | Unedited, truth-labeled one-take demo using only proven paths |
| Terminal-native breadth | Plan show/lint/export/revise/edit/diff/approve, run/status/watch/why/bundle, cancel/retry/request-replan, and private task input exist; model-generated replan, arbitrary mission replay, cross-run diff-runs, and a TUI are absent. `plan diff` is a structural diff over the canonical model — it names changed nodes, edges, per-field scope changes, and flags a scope that only grew — not a semantic diff of intent | Add only workflows backed by existing durable authority when the live path needs them |
| Human identity | Confirmed local-terminal truth durably includes a bounded hash of the local OS uid and password-database username in the public operator label; this is not external authentication | Add an authenticated identity provider before claiming external principal assurance |

The legacy Auth protocol tour remains supported as a regression surface, not as Taskmaster proof. Current mission-plan validation rejects its reserved `legacy_auth_v2` attempt link.
