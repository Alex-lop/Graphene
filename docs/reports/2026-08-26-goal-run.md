## Overrides taken, and why

1. **CP-A2 landed before CP-A1.** `test_readme_contract.py` requires every registered command to be documented, so a README with "Shadow nowhere" is only green once the `shadow` command is gone. The deletion commit came first; both are Phase A commits behind the same gate.
2. **`test_readme_contract.py` and `test_capsule_cli.py` follow the content they check.** The directive freezes `test_graph_economics_deferral.py` and `test_documentation_truth.py` (unchanged); it moves the proof table to `docs/PROOF.md`, so the assertions that pinned proof rows and the command map to `README.md` now pin them to `docs/PROOF.md` and `docs/COMMANDS.md`. No assertion was dropped; one was added (the 120-line cap).
3. **The safety-boundary sentences moved into `docs/TASKMASTER_PRODUCT_CONTRACT.md`**, not deleted: the frozen doc-truth test requires them in one of four canonical documents, and the product contract is where an authority boundary belongs.
4. **`docs/DEMO_GUIDE.md` is not deleted** although the directive names it as a candidate: `test_graph_economics_deferral.py::test_no_public_surface_claims_a_measured_economic_advantage` asserts the file exists, and that test is frozen by the same directive. Rule 3 ("never delete anything a green CI job consumes") decides it.
5. **Textual over Rich Live, decided once.** The acceptance needs key handling (select, drill in, quit with the terminal restored) and headless snapshot tests; Textual's `run_test` pilot gives both, a Rich Live loop would need a raw-mode terminal shim and its own test harness. Cost: `textual==8.2.8` plus three pure-Python packages in `uv.lock`. The renderer stays pure (`dag_render.py`) so the tests assert what the screen shows.
6. **Evidence for CP-B2 is dated 2026-08-26**, the day it was captured, not the 2026-08-27 the directive pencilled in; evidence is dated by capture.
7. **The Phase A gate ran in a clean worktree at the pushed commit, not in the working tree**, so Phase B work in progress could continue without being overlaid into the Linux parity check. The push itself came from the working tree at the same commit.
8. **`approve_plan` over MCP runs the mission synchronously**, as the CLI's `approve-plan` does, rather than in a background thread: the scripted fixture finishes in about seven seconds, a live run in under a minute, and a thread whose owner process is the MCP client's child would die with the session. The tool's own text says approval starts execution.
9. **The E2E signer is the script.** CP-C3 asks for a scripted E2E; the transcript names the operator as "scripted operator (not a person)" on the signing beat and the label's truth text says no person signed in a chat client.
10. **Connect blocks carry a date, not a claim.** `graphene-mcp` today needs `GRAPHENE_LINEAGE_DB` and a `--task`; the bare launch form, `.mcp.json`, and the `goal` prompt are Phase C. The README says so beside each block rather than describing a surface that does not exist yet.

## Systemic findings

1. **A required link and a frozen link test force a placeholder file.** The directive asks for an image link before the image exists while freezing the test that resolves every link; the honest resolution is a file that says it is a placeholder, not a missing file. Replaced by a real capture in Phase B.
2. **The macOS parity venv under `$TMPDIR` had rotted.** Its first run this session failed at collection with a `StopIteration` inside opentelemetry's entry-point loader: the reused environment in `/var/folders/.../T` had lost files (macOS prunes that directory). A parity check that reuses an environment it does not verify is a check whose environment can decay under it. This run keeps the venv under `~/.cache` and rebuilt it from the lock.
3. **The macOS parity check cannot run in a clean checkout as written.** Thirteen process tests exec `.venv/bin/graphene` literally, so a gate worktree with no `.venv` fails all of them with `FileNotFoundError` while looking like product failures. `scripts/macos_parity_check.sh` now links `.venv` to the parity environment for the run when it is absent — which is exactly what CI's `.venv` is — and says so in its header.
4. **An in-process reader beside the scripted runner wedges.** The first live-follow test ran the mission in a thread and polled the store from the test thread; it hung past 400 s in the shape `docs/KNOWN_LIMITATIONS.md` documents (SQLite VFS inode mutex under connection churn). The viewer is a separate process in real use, the evidence capture already used one, and the test now does too. The hang row stays exactly as written.
5. **A viewer that attaches before the first attempt never sees the evidence store unless it looks again.** `attempt-evidence.sqlite3` does not exist at proposal time; binding it once at start-up left the projection refusing every snapshot after the first publication ("materialized state failed store validation"). The source now binds the read-only evidence handle lazily on each poll until it exists. The first evidence capture shows the symptom; the committed one shows the fix.
