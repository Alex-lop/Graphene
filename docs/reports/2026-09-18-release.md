## 2. What works

Release engineering (M2)

- `pyproject.toml` is complete for PyPI: the one-line description (the same sentence is the GitHub
  description now), author from `git config`, `license = "Apache-2.0"` with `LICENSE` attached (its
  placeholder copyright line filled), URLs, keywords, classifiers, `requires-python = ">=3.12"`.
  Python 3.12 needed no code change: `uv run --python 3.12 pytest -q` passed all tests. The name is
  free: `curl -s -o /dev/null -w "%{http_code}" https://pypi.org/pypi/graphene-debrief/json` → 404.
- The wheel works alone: `uv build`, `twine check` PASSED for both artifacts; the wheel installed into
  a fresh venv and into a fresh `UV_TOOL_DIR`, run from `/tmp`, prints `graphene 0.1.0` and the help.
  `unzip -l` shows `graphene_debrief/templates/record.html` and `licenses/LICENSE` inside it.
- `.github/workflows/ci.yml`: ubuntu-latest and macos-latest × Python 3.12 and 3.13, each running
  `uv sync`, `ruff check`, `pytest -q`, `uv build` and a wheel smoke from `$RUNNER_TEMP`.
  `.github/workflows/release.yml`: on a `v*` tag, build, smoke, then publish with
  `pypa/gh-action-pypi-publish@release/v1` under `environment: pypi` with `id-token: write` and no
  secret. Both lint clean with yamllint. `docs/RELEASING.md` (39 lines) says how to cut a release and
  what to configure on PyPI the first time.
- Schema versioning: the store carries `PRAGMA user_version = 1`. A store from another version, or a
  file SQLite cannot read, is moved to `.graphene/graphene.db.v<old>.bak` (or `.corrupt.bak`, never
  overwriting an earlier backup, sidecars included), a fresh store is created and backfilled, and one
  line on stderr says so. The hook never rebuilds: on such a store it skips the event, writes one
  line to `.graphene/ingest.log` and exits 0. This happened for real tonight: this repo's 67 MB v0
  store went to `graphene.db.v0.bak` on the first `graphene` after the merge, 26 sessions were
  reloaded in about 3 s, and `ingest.log` shows the hook skipping events in between.
  tests/test_store.py, tests/test_cli.py.
- Backfill is incremental: the transcript's size and mtime are stored, an unchanged transcript costs
  one `stat`. 200 synthetic sessions load in about 5 s; the second run parses nothing.
  tests/test_scale.py (marked `slow`, runs in CI). Because it is cheap, every command now tops the
  store up from the transcripts, so a second session shows up in plain `graphene` without
  `graphene init` (before tonight only an empty store was backfilled). tests/test_cli.py.
- A hook-recorded session is rebuilt from its transcript automatically when the hooks are installed
  in the repo and the transcript holds more tool calls than the hooks captured; the hook-captured
  HEAD and the earlier start time are kept. tests/test_backfill.py.
- `graphene debrief --explain claude --model NAME` passes `--model` to `claude -p`; the default is
  `haiku`, checked with one real one-word call (`claude-haiku-4-5-20251001`, `total_cost_usd`
  0.010). The model name is stored beside each sentence and appears in `--json`.
  tests/test_explain.py.

The terminal (M3)

- One accent colour (cyan) for paths and commands, dim for timestamps and metadata, green only for
  `+N` and red only for `−N`, bold only on the header line, no boxes, no emoji. The card is capped at
  5 commits, 20 files and 6 rows per tail section, so it fits 40 rows at 80 columns (a test renders a
  30-file, 24-commit session and asserts ≤ 40 rows and ≤ 80 columns). Piped output is the plain
  markdown text (`graphene > out.txt`), `NO_COLOR` leaves no escape codes. `why` and `sessions`
  follow the same rules. tests/test_cli.py, tests/test_debrief.py.
- Seven one-line empty states, each tested: outside a git repository; inside `$HOME`; no transcripts
  found (says where it looked, then what to do); transcripts but no file changes; store locked (at
  open, or mid-command); `why` on a path never seen; `why` with no path (five most recently changed
  files, then the usage line).
- `graphene --help` lists `why` and `debrief` first and `init`, `sessions`, `ingest` under Advanced;
  `debrief --help` says it is the short card and that `--full` is the reconstruction.
- `docs/assets/render_assets.py` renders `card.svg`, `why-path.svg` and `why-line.svg` from the
  synthetic fixture into a temp git repo (byte-identical on rerun, no real paths; a test runs it).
  I rasterised all three and looked at them.

The HTML record (M6)

- `graphene debrief --html PATH` writes one self-contained file: the `--json` structure (now with
  hunks per file) embedded as JSON, sessions, prompts, files and directories as distinct node types
  in the data and in the markup, a timeline of prompt rows with file chips, a right-hand panel with
  the diff, the sentence and the file's history within the record, two filters, one accent colour,
  dark mode, no network of any kind. Template, CSS and JS are 444 lines. tests/test_export.py
  (embedded JSON round trip, every prompt and path present, no placeholder, `</script>` escaped,
  no URLs or `innerHTML` in the template, `node --check` on the page script). The building agent
  and I both opened it in a headless Chromium (served from localhost, since the browser tool
  refuses `file://`), light and dark, clicked a file, toggled a filter; the console was clean.

- Claude Code puts its worktrees under `.claude/worktrees/` inside the repo, so a session that
  delegates to worktree agents listed every file they touched as this repo's (30 rows of
  `.claude/worktrees/agent-…/…` on tonight's card). A path inside a nested git checkout now counts
  as outside the repo (path only, no content) in the hook, the backfill and the shell-command scan.
  tests/test_attribute.py.
- `debrief` was in the Advanced panel and `init` in the main one; swapped, per the directive.

## 5. Decisions you should check

Repo mechanics

- You had merged `rebuild` into `main` yourself through PR #23 on 2026-09-17 (merge `a2504a8`,
  everything up to `dbf7da7`); local `main` was still at the `hackathon-2026` tag. The gated merge
  therefore fast-forwards local `main` to `origin/main` first and then merges `rebuild` with
  `--no-ff`. The directive's rollback command (`git reset --hard hackathon-2026 && git push --force
  origin main`) would also undo your PR #23; it is in morning.md verbatim as asked, with that note.
- The four worktree agents' commits were cherry-picked onto `rebuild`, not merged, so the history
  stays linear. Their worktrees are still under `.claude/worktrees/` (git-ignored); delete them
  with `git worktree prune` after `rm -rf .claude/worktrees` if you want the space back.
- The uncommitted `REPORT.md` diff you left was editor reflow damage (list indentation stripped, a
  merged-line typo), not content; I restored the committed version and kept the diff as a patch in
  the session scratchpad instead of committing it.
- Commits carry no attribution trailers, per the repo convention.
- Size: 3,437 lines of non-test Python (tests: 3,073), up from 2,646 yesterday. The additions are the
  terminal renderer (about 170 lines), the HTML export (113 plus the 444-line template), schema
  versioning and incremental backfill, the empty states and the nested-checkout rule. The
  rebuild directive's "~2,500" was not restated tonight; easy cuts if you want them: `from_json`,
  the `ingest hook` Typer alias, `print_sessions` (a Rich table with `box=None` would do).
- The banned-word rule now holds for every tracked file except LICENSE: yesterday's report had two
  mentions (a moved file's name and a note about a quoted sentence); both are reworded.

Product

- `requires-python = ">=3.12"`: it passes today, but it is a support promise (CI is 4 jobs).
- Every command tops the store up from the transcripts. It costs one `stat` per transcript when
  nothing changed and a parse of the live session's transcript while a session is running
  (tenths of a second here).
- The haiku default for `--explain claude` lives in `pick_explainer`; a directly constructed
  `ClaudeCodeExplainer` still sends no `--model`.
- The hook skips the event on a stale or corrupt store rather than rebuilding (rebuilding takes
  seconds and the hook has a 35 ms budget); the transcript backfill recovers the skipped events.
- A file inside a nested git checkout counts as outside the repo. This is right for
  `.claude/worktrees/` and vendored clones; a submodule you meant to track would be hidden the same
  way.
- The terminal card folds "Commits during the session" into the second header line, drops the
  `--full` pointer from the failures line (the closing line points at it), and caps tail sections
  at 6 rows. The markdown card (`--md`, piped output) is unchanged: 30 files, every commit.
- `NO_COLOR` takes the plain-text path entirely, because Rich's own `no_color` still emits bold and
  dim escapes.
- A bare slash-command line (`/model`, `/plugin:skill args`) is not a prompt, in the hook and in the
  transcripts; a prompt that merely starts with a path (`/tmp/x.py is broken`) still is.
- The HTML record embeds `{"debrief": …, "nodes": […]}` rather than the bare debrief; "abandoned"
  there is matched by path across the whole export.
- GitHub topics: the three hackathon-era ones (`agent-orchestration`, `agentic-ai`,
  `agentic-workflow`) are still there because the directive said add, not replace.
